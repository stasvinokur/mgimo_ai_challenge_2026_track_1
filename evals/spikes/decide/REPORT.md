## Главное (спайк 2026-11-04, до ключа Jev)

1. **Jev вживую не проверен**: ключей `TYPESAFE_API_KEY` и `OPENROUTER_API_KEY` нет, `jev_probe.py` пишет
   «ключа нет, пропуск» и выходит с кодом 0. Нативный эндпоинт существует: без ключа — 403 «Must supply an
   API key». В публичном каталоге OpenRouter есть только `typesafe/jev-router` — маршрутизатор LLM для chat
   completions, а не System One; `typesafe/jev-latest/endpoints` — 404. Путь через OpenRouter decide()
   с вероятностями, скорее всего, не даст.
2. **В Ollama Cloud есть модель решений Clef** (`clef:cloud`, 27B, Cloudflare, Apache 2.0). Она работает
   через **System One API** демона (`POST /v1/systemone`, в клиенте есть `ollama.systemone`). Это тот же
   протокол, что у Jev: `state` + `questions{choice|noul|score}` → вероятности. Clef доступен без новых
   ключей и **работает по-русски**: 37/38 = **97,4%**, p50 **0,44 с**. Перестановка вариантов не поменяла
   ни одного ответа, переименование меток — 2,6%, на отрицание вопроса Clef ответил согласованно в 24 из 24.
3. **Запасной LLM-вариант** — локальная `gpt-oss:20b`, enum через `format`, `think=low`: 35/38 = **92,1%**,
   p50 1,6 с, денег не стоит. Устойчивость слабее: перестановка меняет 14% ответов, переименование — 7%
   (на 14 примерах про тип утверждения).
4. **logprobs не дают уверенности.** Облачные модели Ollama logprobs не отдают и `format` игнорируют
   (см. evals/spikes/models/REPORT.md). Локальная gpt-oss их отдаёт, но она рассуждает: токен ответа выбирается
   уже после рассуждения, поэтому p ≈ 1,000 у всех 38 примеров, включая 3 ошибки. Самооценка `confidence`
   тоже бесполезна (0,95–0,99 и на ошибках). Ни один порог ошибки не ловит.
5. **Рабочий сигнал уверенности — расхождение вариантов вопроса.** Перестановка или переименование: если
   ответы разошлись — эскалация. У Clef варианты уходят в том же запросе, задержки не добавляют. Так поймана
   1 из 1 ошибки у Clef и 1 из 1 у LLM на подвыборке с вариантами; при согласии вариантов точность 100% у обоих.
6. **Рекомендация.** decide() по умолчанию — бэкенд System One с Clef. Эскалация при **p_max < 0,7**
   или при расхождении вариантов. Jev — второй профиль того же бэкенда, когда будет ключ и он пройдёт этот
   набор. LLM — запасной путь на случай недоступности System One; порог уверенности для него не работает.

`confidence` в ответе Clef измеряет концентрацию распределения, а не вероятность правоты (так в документации;
ECE = 0,30). Порог ставим по `probabilities`.

подвыборке «тип утверждения» поймало 1 из 1 ошибки при 1 ложной тревоге.

**Порог:** `confidence_threshold: 0.7` по вероятности System One (уже в `config/models.yaml`); эскалация —
примерно каждый десятый вопрос. Для критичных вопросов («обещание = продукт», сильное возражение) в тот же
запрос добавляется переставленный вариант, при расхождении — эскалация. Выборка мала (38), поэтому порог надо
пересмотреть по журналу реальных вызовов в TASK-7: фиксировать «неверный маршрут», когда сильная модель
не согласна с decide().

## Jev: известно и не проверено

Из открытых источников (вживую не проверено):
- Запрос: `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer $TYPESAFE_API_KEY`, тело
  `{"model": "jev-1.13.0", "state": …, "questions": {id: {"type": "choice"|"noul"|"score", "instructions", "criteria"}}}`,
  без temperature. Формат совпадает с типами `SystemOne*` клиента ollama, поэтому `jev_probe.py` переиспользует
  вопросы и разбор ответов Clef; разбор терпит `probability` вместо `noul` и отсутствие `probabilities`.
- Модели: `jev-1.13.0`, `jev-1.14.0`, `jev-latest`, `jev-preview`.
- Лимиты: 64k токенов на запрос и 32k на вопрос; Choice до 255 вариантов, Score 2–10 уровней. Заявлены 70–500 мс
  и 1200 запросов в минуту; AI SDK повторяет 429 и 529. В AI SDK noul называется `boolean`, смешивать
  с нативным названием нельзя.
- Цена: $0,042 за 1 млн входных токенов, выход бесплатно, бесплатного тарифа нет. Это в ~6 раз дешевле Clef,
  но обе модели стоят меньше 0,01 ₽ за вопрос.
- Доступ: нативный API — по листу ожидания. OpenRouter — см. выше. Vercel AI Gateway (`typesafe-ai/jev`,
  только JS AI SDK) и Cloudflare AI Gateway (`typesafe/jev`, `/ai/run`). Python SDK `typesafe-sdk`
  не устанавливали: `uv add` запрещён, а httpx хватает.

Не проверено: качество на русском, чувствительность к названиям вариантов (вендор её признаёт), латентность
из РФ, оплата из РФ, точная форма ответа.

## Маршрутизация decide()

| Вопрос | По умолчанию | Когда появится ключ Jev | Запасной путь |
|---|---|---|---|
| Тип утверждения (choice, 7 классов) | Clef | Jev, если на этом наборе точность ≥ 95% и смена ответа ≤ 5% при перестановке и переименовании | LLM `workhorse`/`local_small`, канонический порядок |
| Сильное возражение (noul) | Clef + переставленный вариант в том же запросе | Clef, пока Jev не пройдёт трудные `ob04`, `ob09`, `ob11` | LLM → эскалация к `reasoning` |
| «Обещание = продукт» (noul) | Clef + отрицание в том же запросе | как выше | LLM → эскалация |
| Оценка по шкале (score) | Clef (2–10 уровней, дробная оценка с вероятностями) | Jev | LLM, шкала через enum |
| Контекст > 64k токенов | — (Clef в облаке отклоняет больше 65 536) | — (у Jev 64k) | LLM или сжатие state |
| Нужно текстовое обоснование | — | — | LLM (System One даёт только вероятности) |

Эскалация к `reasoning` — при p_max < 0,7, при расхождении вариантов, при ошибке или недоступности System One.
Для TASK-7: нужен общий бэкенд `systemone` с двумя профилями — `clef:cloud` через демон (`/v1/systemone`,
без ключа) и Jev (`https://api.typesafe.ai/v1/systemone`, `TYPESAFE_API_KEY`); код запроса один. Структура
`config/models.yaml` не менялась: рекомендация записана комментарием в секции `decide`.
