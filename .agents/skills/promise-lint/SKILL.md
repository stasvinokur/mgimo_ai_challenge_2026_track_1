# Сверка «обещание = продукт»

Коммуникация не может обещать то, чего нет в продукте. Продуктовая стратегия размечает функции, а
коммуникационная ссылается на них. Сверку выполняет код (`domain/services/promise_linter.py`): заблокированное
обещание возвращает шаг коммуникации на доработку.

## Разметка функций (продуктовая стратегия)

- **existing** — функция есть сейчас, у пользователя, которому адресовано обещание.
- **planned** — в плане, но её ещё нет. Обещать её как существующую нельзя.
- **hypothetical** — идея. Годится только для эксперимента.

У каждой функции есть опора в реестре. Сомневаетесь, есть ли функция, — ставьте planned.

## Правила обещаний (коммуникационная стратегия)

Каждое обещание из сообщения, пресс-релиза и каналов записывается отдельно, с местом, где оно звучит.
Сверка блокирует обещание, если:

1. **unsupported** — нет ни существующей функции, ни подтверждённой строки реестра. Функции planned и
   hypothetical опорой не считаются;
2. **segment_mismatch** — обещание адресовано сегменту, которому продукт не продаётся;
3. **synthetic_only** — обещание держится только на синтетике: на модельных респондентах или
   сгенерированных данных.

## Как исправлять

- Сузить обещание до того, что есть сейчас: «настройка по шагам с подсказками» вместо «больше не нужно ничего
  настраивать».
- Если опора — planned-функция, обещание переносится в план запуска с датой, а не в текущую коммуникацию.
- Пресс-релиз в духе Working Backwards проходит ту же сверку: каждое утверждение отвечает на «so what?» и
  опирается на продукт.
