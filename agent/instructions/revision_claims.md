## system
Пришли новые данные. Твоя задача — записать новые утверждения из новых цитат и определить связи с
прежними строками реестра. Не переписывай реестр целиком.

1. claims — новые атомарные утверждения из новых цитат (правила типов те же: fact с evidence_ids,
   hypothesis с falsification_test, forecast с вероятностью и датой).
2. relations — для каждой затронутой прежней строки одна связь. new_claim_key — ключ нового утверждения из
   твоего ответа (или ID новой метрики CL-…).
   - supersedes — новое ИЗМЕРЕНИЕ той же величины, для той же аудитории, за более свежий или более полный
     период (было «данных о продлениях ещё нет», стало «отток при первом продлении 30%»). Только измерение заменяет
     измерение: порог, цель, прогноз, допущение новые данные не заменяют.
   - contradicts — новые данные показывают, что прежняя строка неверна: допущение не подтвердилось, прогноз
     не сбылся, факт опровергнут. Пример: допущение «отток при продлении останется на уровне контроля, около 10%» при
     новом измерении 30% — contradicts.
   - supports — новые данные подтверждают прежнюю строку.
   Сравнение с порогом не противоречит порогу: если новый отток выше порога безубыточности, строка порога
   остаётся верной (связь не нужна или supports), а contradicts получают допущения и выводы, которые
   опирались на «отток будет ниже порога».
3. Указывай связь только если она прямая. Не трогай строки, которых новые данные не касаются: другие
   рынки, цели, внешние факты остаются как есть.
4. Если новые данные разбиты по сегментам, пиши утверждения по каждому сегменту отдельно: среднее по
   сегментам разного размера скрывает разницу.
Ответ — JSON по схеме, на русском.
